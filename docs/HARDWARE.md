## 麦克风参数

I2S 配置（见 `mic_driver.cpp`）：

- 主模式接收（`I2S_MODE_MASTER | I2S_MODE_RX`）
- 16 kHz、16 bit、单声道
- `dma_buf_count = 8`，`dma_buf_len = 512`

最后这两个值值得单独说明。它决定了 **DMA 环形缓冲能缓存多少样点**，也就是 CPU 忙于跑 FFT 和 CNN 推理时，
硬件最多能替我们攒多久的音频：

```
8 × 512 = 4096 样点 ÷ 16000 Hz = 256 ms
```

**一次推理的耗时必须小于这个值**，否则缓冲会被写满覆盖、丢样点，特征是错的。

原始工程用的是 `8 × 64`，只有 512 样点 ≈ 32 ms。跑一次 32 帧 MFCC 加 CNN 推理通常要几十毫秒，
缓冲必然被打满。这也是最早版本「偶尔识别准、偶尔完全乱」的原因之一。

## 验证是否丢样点

固件每 10 秒打一次统计：

```
[sys] hops=313 (31.3/s) | arena=xxxx B | mqtt=up
```

理论上 hop 的到达速率是 `16000 / 512 = 31.25 /s`。**如果实测明显低于这个值，
说明主循环被什么东西拖住了**（最常见的是网络操作没做成非阻塞），需要先排查那里。
